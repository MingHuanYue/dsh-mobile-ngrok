# 溟月 · 手机端 DeepSeek Harness

用 ngrok 把电脑上的 DeepSeek Harness 搬到手机浏览器或者apk里。

会话、文件、工具、记忆都是电脑上那一份，手机只是个窗口。

---

## 这东西怎么工作的

手机上跑一个 WebView 应用，电脑上跑一个网关，中间用 ngrok 隧道连起来。

网关是必须的。DSH 本身只监听 `127.0.0.1`，这是故意的——把 3080 端口开放到网络上，
等于把这台电脑交给任何能连上它的人。所以中间放一层网关：它转发请求给 DSH，
但每个进来的请求都得先过令牌这一关。

ngrok 也是必须的，如果你手机用流量、电脑插网线的话。这种情况两台设备
根本不在同一个局域网，填什么内网地址都连不通，只能走公网隧道。

---

## 怎么用

### 电脑这边

先启动 DSH，再启动网关。

网关就是 `gateway/` 目录里的那个控制台程序（`手机网关控制台.exe`）。
双击打开，点「一键启动」，它会依次把网关和 ngrok 隧道拉起来。

启动完控制台会显示一个 `https://xxx.ngrok-free.dev` 地址，这是手机要填的。

另外 DSH 启动的时候会打印一串带 `token=` 的地址，`token=` 后面那串字符也要记下来。

### 手机这边

装上 APK，打开，点「填地址」，把上面两个东西填进去：地址填 ngrok 那个网址，
令牌填 `token=` 后面那串。地址不用自己加 `https://`，它会补。

保存之后回到主界面就能用了。

第一次进去会弹一个「内测声明」，点「继续」就行。那是 DSH 自己的公告，
电脑上每次重启 DSH 也会弹，不是这里的毛病。

## 仓库里有什么

```
android/    手机应用。Java 写的 WebView 外壳，不用 Gradle
gateway/    电脑端。网关进程 + 那个可视化控制台
compat/     给旧浏览器内核补 API、修排版用的脚本
docs/       详细一点的使用说明
```

**android/** 这部分本身没有任何智能，它就是个浏览器窗口。代码里花力气最多的地方
是保活：息屏、切后台、渲染进程被系统杀掉之后，怎么把页面弄回来。

**gateway/** 里 `gateway.js` 是个不依赖任何第三方包的 Node 反向代理，
负责转发和令牌校验；`gateway-console.cs` 是带界面的控制台，用 C# WinForms 写的。

**compat/** 解决的是浏览器内核太旧的问题。手机自带的内核往往比 DSH 前端要求的版本低，
差的部分分两类：一类是语法不认（比如类静态块 `static{}`，解析阶段就报错），
一类是缺运行时方法（比如 `Promise.withResolvers`）。前者只能转译，后者能用 polyfill 补。
这些脚本改的是你电脑上已经装好的 DSH，不是这个仓库里的文件。

## 自己编译 APK

不用 Gradle，`android/build-apk.ps1` 就够了。需要 JDK 和 Android SDK 的 build-tools
（aapt2、d8、zipalign、apksigner 这几个）。

```powershell
powershell -ExecutionPolicy Bypass -File android/build-apk.ps1
```

脚本会把要编译的文件先复制到 `%TEMP%` 下的一个纯英文路径再动手。因为 aapt2 打不开
带中文的路径。这个坑踩过一次，别改掉。

## 一些已知的问题

**长时间息屏后可能要重开一次。** 部分机型（我手上测试的华为鸿蒙就是）息屏久了之后，
WebView 会把页面的 `visibilityState` 一直留在 `hidden` 不再改回来。浏览器在这种情况下
会停掉 requestAnimationFrame 和渲染，页面看着还在、JS 也还能跑，但一帧都不画、
点也没反应。这是系统内核的行为，应用层试过几种办法都改不动，只能重开。

**横屏不套用窄屏排版。** 排版修正用的是 `@media (max-width: 520px)`，
横屏的视口宽度通常超过这个值，所以会回到 DSH 原版的样子。不会坏，只是不优化。

**ngrok 免费版有限制。** 流量和并发都有上限。免费隧道第一次访问会给浏览器
弹一个警告页，这里通过改 User-Agent 绕开了。

**别拿它当正经的鉴权系统用。** 网关的令牌机制够日常用，但别把这东西暴露到
不受信任的网络上。

## 换别的手机能不能用

窄屏排版用的是相对宽度，没有针对某一台设备写死像素值。正常情况下换个手机也能用。

不过有几个数值是实测出来的，比如左导航在窄屏下固定 120px。这个数字不是拍脑袋定的：
每个标签最多需要 56px（最长的是「Agent 预设」），加上图标 16px 和间距 8px，
再算上左右内边距，120px 刚好够；试过 112px 会把「Agent 预设」截断。

选择器是按类名中段匹配的，比如 `[class*="_nav"]`，因为 DSH 的类名带构建时的哈希前缀。
如果哪天 DSH 升级后把类名改了，这些样式会静默失效。失效的时候页面不会坏，
只是不再优化。

想确认某台手机上有没有生效，看应用底栏 `⋮` → 查看页面诊断里的 `innerW` 值。
小于 520 就是生效了，大于 520 说明是横屏或者平板。

## 踩过的坑

这部分可能比代码有用。下面每一条都是真的踩过。

### 前端

注入的 `<script>` 一开始放在了 DSH 自己的脚本后面。DSH 那些脚本先执行，
那时候补丁还没生效，等于白写。注入必须排在 `renderIndex` 之前。

用 `!important` 把挂件的 `--dshw-scale` 锁死了，结果挂件拖不动、大小也调不了。
因为 `!important` 的样式表规则会压过元素自己的内联样式，而挂件正是靠内联样式
在拖拽时改位置、拉滑块时改缩放的。**第三方组件的动态状态不能从外面锁。**

还有一次把状态烘进了闭包，写成 `var want = <安装时的值>`。装好之后就固定了，
后面怎么改都没用。

挂件状态的判断一开始只放在 `onPageFinished` 里做一次。但挂件是页面加载完之后
才自己创建出来的，那一次判断的时候它还不存在，所以关不掉。后来改成用
MutationObserver 一直盯着。

### Android

WebView 的 LayoutParams 类型跟父容器对不上，`weight` 被忽略、高度算成 0。
表现是页面看着在、其实点不动。诊断日志里能看到 `web=1080x0`。

`emptyState` 和 WebView 都带 `weight=1`，两个抢空间，WebView 只剩半屏。
覆盖层应该用 `match_parent`，不该参与权重分配。

`applyIntentOverrides()` 被放在了视图绑定之前调用，里面 `showToast()` 抛了空指针，
异常被 catch 吞掉，导致它后面的 `Prefs.save()` 整段跳过，配置根本没存下来。
找这个问题花了很久。

`View.onWindowVisibilityChanged()` 是 protected 的，外部调不到，编译就报错。

### 怎么判断问题

`netstat | findstr` 判断服务死活误报了三次，说 DSH 挂了，其实一直活着。
后来一律用真实的 HTTP 请求验证。

看布局问题真的魔了。最后一次把手机用数据线连上电脑，
`chrome://inspect` 才看到真正的原因：那条 `padding-right: 48px` 把文字挤没了。

有一次先下了结论再验证，据此做了一次全量回退，把必需的 polyfill 撤掉了，
结果更糟。

### Windows 的编码问题

`.cmd` 文件里不能写中文，只能纯 ASCII 加 CRLF。中文是多字节的，会让 cmd 的
解析器错位，把后面的命令切碎，连 `rem` 注释都能被当成命令执行。

`.ps1` 里也别写中文。PowerShell 5.1 会把没有 BOM 的 `.ps1` 当 ANSI/GBK 读，
UTF-8 的中文路径会变成乱码。
