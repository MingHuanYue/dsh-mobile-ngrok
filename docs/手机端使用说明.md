# DSH 手机端 · DSH 手机端

在手机上用完整的 DSH —— 同一个会话、同一份文件、同一套工具和记忆，不是另一个只会聊天的壳。

```
手机端/
├── out/mingyue-dsh.apk      ← 装到手机上的东西（301 KB，鲸鱼娘图标）
├── assets/whale.png         ← 图标源图（小鲸鱼立绘）
├── app/                     ← APK 源码（Java + XML，没有 Gradle）
├── build-apk.ps1            ← 一条命令重新打包
├── 说明.md                   ← 本文件
├── mingyue.keystore         ← 签名密钥（别删，删了升级装不上）
└── 网关/                     ← 电脑端网关（Node，零依赖）
    ├── gateway.js
    ├── 启动网关.cmd           ← 双击这个（手机和电脑同网时用）
    ├── 启动隧道.cmd           ← 手机走流量/电脑走校园网时用（ngrok）
    ├── start-tunnel.js
    ├── ngrok.exe            ← 官方版，签名已验证（ngrok, Inc.）
    ├── 放行防火墙.cmd         ← 手机提示「拒绝」时双击（弹 UAC）
    ├── 网络自检.cmd           ← 连不上时先双击这个
    ├── 管理自检.ps1           ← 网络自检指向它时，右键以管理员运行
    ├── net-check.js         ← 上面那个的实体（不需要任何权限）
    ├── test-gateway.js      ← 16 项自测
    └── live-probe.js
```

> 文件名和脚本里凡是 ASCII 能表达的都用了 ASCII，这不是偷懒，是被编码坑怕了。
> 原因写在最下面「踩过的坑」那一节。

---

## 为什么需要一个网关

DSH 故意只监听 `127.0.0.1`，而且**明确拒绝** `--host 0.0.0.0`：

> `error: --host 0.0.0.0 is intentionally not supported yet for safety: it would
> expose remote code execution to the network; use 127.0.0.1 instead`

这是对的——DSH 能读写文件、执行命令、控制整台电脑，直接开到局域网上等于把电脑交出去。

所以这里没有去撬开 DSH，而是**在它门口放了一个有门禁的网关**：网关面对局域网，DSH 依然只听本机。任何请求进 DSH 之前，都要先在网关这儿过令牌这一关。

---

## 先选路线：手机和电脑在不在同一个网络？

这一步决定了后面完全不同，**别搞混**：

| 情况 | 判断 | 走哪条 |
|---|---|---|
| **同一个网络**（手机连的 WiFi 和电脑是同一张） | 手机浏览器打开 `http://电脑局域网IP:3081/` 能看到「需要访问令牌」页 | 下面的「局域网路线」 |
| **不在同一个网络**（例：手机走流量，电脑走校园网网线） | 上面那个地址永远转圈，因为两台设备根本没有互相可达的路径 | 下面的「隧道路线」 |

> 手机走流量、电脑走校园网网线，是**最常见也最容易被误判**的情况。局域网地址不是"配置错了"，
> 是物理上不可能通——必须用隧道。校园网通常还禁入站，所以任何"局域网直连"的方案都不成立。

## 局域网路线（手机和电脑同一个 WiFi）

### 1. 电脑：先起 DSH

双击上级目录的 `Start-DSH.cmd`。

控制台会打印一行带 `token=` 的地址，**把 token 后面那一串复制下来**：

```
dsh web: http://127.0.0.1:3080/?token=AbC123...xyz
```

> 没有这一行？用启动器重新起一次就有。**重启 DSH 会换新 token。**

### 2. 电脑：放行防火墙（只需做一次）

双击 `网关\放行防火墙.cmd` → 弹 UAC → 点「是」。

它会只放行网关端口（默认 3081）的入站 TCP，只对「专用/域」网络生效，
**不碰 DSH 自己的 3080**。公共 WiFi（咖啡厅那种）不会被打开。

> 跳过这步的话，手机会一直提示「连接被拒绝」——因为包在碰到网关之前就被防火墙丢了。
> `启动网关.cmd` 会自动检测这条规则存不存在，没有就提醒你。

### 3. 电脑：启动网关

双击 `网关\启动网关.cmd`。它会问你要 token，粘进去回车：

```
  DSH 手机端 · DSH 手机网关
  --------------------------------------------------
  DSH      : http://127.0.0.1:3080
  listening: 0.0.0.0:3081
  token> █
  ✓ 令牌有效，手机上直接填这个地址就能进：
  手机地址 : http://192.168.1.5:3081
```

（也可以直接回车跳过，之后在手机浏览器里用带 `?token=` 的地址登录一次。）

**这个窗口要一直开着**，关掉网关就断了。

### 4. 手机：装 APK，填两个格子

把 `out\mingyue-dsh.apk` 传到手机安装（第一次要允许「安装未知来源应用」）。

打开「DSH 手机端」，它会直接跳到设置页，填两样：

| 格子 | 填什么 |
|---|---|
| 电脑地址 | `192.168.1.5:3081` ← 网关打印的「手机地址」，**不用**写 `http://` |
| 访问令牌 | 第 1 步复制的那串 token |

按「测试连接」——显示绿字「通了」就对了，按「回到会话」开用。

> 端口是**网关的 3081**，不是 DSH 的 3080。填错是最常见的坑。

## 隧道路线（手机和电脑不在同一个网络）

**这条路手机端一个 App 都不用装** —— 电脑主动往外连一个中转服务，拿到一个公网 https 网址，
手机用浏览器或本 App 打开那个网址就行。

### 最省事的方式：用控制台（推荐）

**双击 `网关\手机网关控制台.exe`** —— 一个窗口管完所有事：

| 界面上有什么 | 作用 |
|---|---|
| 四行状态 | DSH / 网关 / 隧道 / 防火墙，实时显示「运行中」还是「没运行」（每 1.5 秒真去查一次，不是猜的） |
| 「一键启动（网关 + 隧道）」 | 按顺序起网关、等它就绪、再起隧道 |
| ngrok 令牌输入框 | **粘进去点「保存令牌」就行**，不用手改配置文件 |
| 「手机要填的地址」 | 隧道一起来就把公网网址显示出来 |
| 「复制手机要填的地址」 | 一键复制那个网址 |
| 「本机打开聊天」 | 电脑浏览器直接进网关页面 |
| 「放行防火墙」 | 弹 UAC 提权放行 3081 端口（只放行这一个，不碰 DSH 的 3080） |
| 日志区 | 网关和隧道的实时输出，出错能看见原因 |

配上 `--selftest` 参数（命令行跑）可以不开窗直接打印全部状态，排查问题用。

> 下面的手动步骤仍然有效，控制台本质上就是在帮你点这些。

### 为什么是 ngrok

| 方案 | 结论 |
|---|---|
| **ngrok** | ✅ **选它**。HTTP/HTTPS 隧道免费、**不需要信用卡**、在线时长无限；这台电脑到它的域名全部可达（实测 `ngrok.com`、`dashboard.ngrok.com`、`bin.equinox.io` 都通） |
| Cloudflare Tunnel | ❌ 这台电脑连不上 —— `1.1.1.1:443` 超时、下载站 DNS 解析失败 |
| Tailscale | ❌ 登录页被校园网挡了（VPN 类服务常被拦） |
| Radmin VPN | ❌ 官方**只有 Windows 客户端**，没有 Android/iOS，协议闭源，做不出手机端 |

### 步骤

**1. 起 DSH 和网关**（和局域网路线一样）

- 双击 `Start-DSH.cmd`，记下控制台那串 `token=`
- 双击 `网关\启动网关.cmd`

**2. 起隧道**

双击 `网关\启动隧道.cmd`。第一次它会要一个 ngrok 令牌：

1. 电脑浏览器打开 <https://dashboard.ngrok.com/signup>
   （可以直接用 Google / GitHub 账号登录，**不用填信用卡**）
2. 登录后打开 <https://dashboard.ngrok.com/get-started/your-authtoken>
3. 复制那串 authtoken，粘到脚本的 `令牌>` 提示后回车

令牌会存在 `网关\ngrok.yml`（**不写 C 盘**，你这台机器 C 盘紧张）。

**3. 拿到网址**

隧道起来后会打印：

```
Forwarding  https://xxxx.ngrok-free.app -> http://localhost:3081
```

脚本也会自己从 ngrok 的本地 API 读出这个网址并高亮打给你。

**4. 手机填这个网址**

把 `https://xxxx.ngrok-free.app` **整个**填进 App 的「电脑地址」（要带 `https://`），
令牌填第 1 步那串。点「测试连接」。

> 隧道走公网，所以**手机用流量反而比连 WiFi 更顺**，不经过校园网那一层封锁。

**5. 窗口别关**

隧道窗口和网关窗口都要一直开着。

### 关于那个警告页

ngrok 免费版会对**浏览器**首次访问插一个警告页。App 里默认把浏览器标识设成了 `MingyueDSH`
（设置页里可改），正常应该不会触发。

真遇到了：

- 先用**手机浏览器**打开那个网址，点一次「Visit Site」，之后再开 App 就好了
  （警告页是按会话记的，点过一次就不再来）
- 或者把设置里的「浏览器标识」改成别的不含 `Mozilla` 的值

### 安全提醒

隧道会把你的 DSH 暴露在一个公网网址上。**网关仍然要求令牌**，不知道令牌就连登录页都过不去
（这台机器上实测过：没令牌连 DSH 的 HTML 都拿不到）。但网址本身是公开可访问的，所以：

- 用完把隧道窗口关掉
- 不要把这个网址发到群里

## 安全边界

- 网关只放行**过令牌**的设备。没令牌的请求只会拿到一张登录页，连 DSH 的 HTML 都看不到。
- 网关握到令牌后，**自己**去完成 DSH 的握手并把会话 cookie 揣在身上，再注入每一次转发；
  网关重启后 cookie 不落盘，需要重新给一次令牌。
- DSH 的浏览器信任围栏（Host 必须是 loopback、Origin 必须等于 Host）由网关自动改写满足，
  DSH 那边一行代码都没改，安全模型没被绕过。
- `.gateway-secret` 是网关签会话 cookie 的密钥，别外传。删掉它下次启动会重新生成。
- 建议把 `网关/` 加进 `..\.gitignore`：里面有密钥，`gateway.config.json` 可能带你的内网地址。

### 手机提示「连接被拒绝」时自查

```powershell
# 1. 网关在听吗？（应该看到 0.0.0.0:3081 LISTENING）
netstat -ano | findstr :3081

# 2. 放行规则在吗？（应该列出 Mingyue DSH gateway）
netsh advfirewall firewall show rule name="Mingyue DSH gateway"

# 3. 手机和电脑是不是同一个 WiFi / 同一网段
```

### 手机提示「超时」——这是另一回事

**「拒绝」= 有人应答但拒绝了你；「超时」= 包发出去没人应。** 后者几乎总是网络路径问题：

| 原因 | 怎么确认 | 怎么办 |
|---|---|---|
| 手机和电脑不在同一张网 | 电脑 `ipconfig` 看 IPv4，手机看 WiFi 详情里的 IP，前三段不一样就是没在一起 | 连同一个 WiFi |
| **公司/园区 WiFi 开了客户端隔离** | 同网段但就是不通；`netsh advfirewall monitor show currentprofile` 里这张网是 **Public** 而不是 Private | 走下面的 VPN 那条路 |
| 防火墙规则没覆盖这张网 | `放行防火墙.cmd` 的规则只作用于 **private,domain**；Public 网络它管不到 | 同上，或把网络改成专用 |
| 网关没跑 / 端口填错 | `netstat -ano \| findstr :3081` 没有 LISTENING | 启动网关；端口填 **3081** |

#### 最快的判定：用手机浏览器打开 `http://<电脑IP>:3081/`

- 出现一张「需要访问令牌」的深色页面 → **网络是通的**，问题在 App 里填的地址/令牌
- 转圈然后超时 → 网络路径不通，继续往下

#### 两个自检工具

**`网络自检.cmd`** —— 双击即可，不需要任何权限。它检查：

1. 网关端口有没有人在听
2. 本机通过**每一张网卡**能不能连上自己的网关（能证明网关本身是好的）
3. 手机上该填哪个地址

**`管理自检.ps1`** —— **右键 → 以管理员身份运行**。防火墙规则和网络位置类型都存在
HKLM 里，普通权限读不到（实测会报「拒绝访问」/「Requested registry access is not
allowed」），所以这部分只能提权跑。它检查：

1. 网关的防火墙规则在不在、覆盖哪个档、开没开
2. **每张网络被归到 Public 还是 Private** ← 这条最关键
3. 当前活动连接的类别
4. 谁在监听端口

**怎么组合着看：**

| 网络自检 | 管理自检 | 结论 |
|---|---|---|
| 端口没人在听 | — | 网关没启动 |
| 全绿 | 规则缺失 | 跑 `放行防火墙.cmd` |
| 全绿 | 手机那张网是 **Public** | 规则管不到它 → 这就是超时的原因 |
| 全绿 | 规则齐全、也是 Private | 那台 WiFi 在更外层就禁止了设备互访，防火墙怎么开都没用 |

#### 最后一条路：点对点私有网络

上面最后一行那个情况下，**唯一可靠的解法**是让手机和电脑走一条点对点私有网络，
用那条网的地址，不要用 WiFi 地址：

| 方案 | 说明 |
|---|---|
| **Tailscale** | 最省事。手机装 App 登录，电脑也装并登录同一个账号，两台就组进同一个私有网段。免费额度对个人够用，不需要公网 IP、不用改路由器。 |
| ZeroTier | 同类，需要建 network ID |
| WireGuard | 自己搭服务端，最可控也最麻烦 |

**Radmin VPN 走不通**：它官方**只有 Windows 客户端**，Android/iOS 都没有
（Play 商店里那个 `com.radminvpn.vpnnowconnectas` 是同名的第三方应用，不是官方）。
它的协议是闭源专有的，没有公开规范 —— 所以**没法"自己写一个 Radmin 客户端"**，
那等于逆向私有协议，不划算也不可靠。

电脑上那条 Radmin 网卡仍然有用：**如果**你哪天有办法让手机进到
那个 Radmin 网络里，它就是现成可用的地址。但目前手机进不去，所以请用上面三种方案之一。

> `启动网关.cmd` 会把电脑所有网卡的地址都打出来，照着挑一个手机能到达的即可。
> 装了 Tailscale 之后，那条 `100.x.y.z` 的地址就会出现在列表里。

## 重新打包

改了 `app/` 里的东西之后：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "手机端\build-apk.ps1"
```

不需要 Gradle、不需要 Android Studio，只用上级 `_buildtools\` 里的
JDK + aapt2 + d8 + apksigner（外加一份 vendored 的 sharp 用来生成图标），
全程约 3.5 秒。脚本最后会自己跑一遍结构校验（清单、资源、中文串、签名）。

换图标：把新图丢进 `assets/`（脚本会取第一个 `.png`），然后重新打包。

## 网关自测

```powershell
cd 手机端\网关
node test-gateway.js     # 16 项：令牌交换、cookie 转发、/api 围栏、WS、过期续期、伪造拒绝
node live-probe.js       # 对着真正在跑的网关打真实请求（需要网关已启动）
```

`test-gateway.js` 里那个仿真 DSH 复刻了真 DSH 的规则（每进程 token、303 + 绑定 authority 的
`dsh-auth-*` cookie、要求 Host=loopback 且 Origin=Host 的 `/api` 围栏），所以它绿了才有意义。

## 踩过的坑（都已在脚本里绕开）

| 坑 | 现象 | 处理 |
|---|---|---|
| **aapt2 不认中文路径** | `error: failed to open directory`（工作区路径里带中文时必现） | 构建输入复制到 `%TEMP%` 下的 ASCII 目录，成品再搬回来 |
| **javac 不认 UTF-8 BOM** | `非法字符: '\ufeff'` | 生成的 `BuildConfig.java` 用无 BOM 写入 |
| **javac 的 @argfile 吃反斜杠** | 路径变成 `C:Users<用户名>AppData...` | argfile 里统一用正斜杠 |
| **javac 找不到 LambdaMetafactory** | `找不到符号 metafactory` | classpath 加 build-tools 的 `core-lambda-stubs.jar` |
| **d8/apksigner 是 .bat** | `JAVA_HOME is not set` | 调用前设 `$env:JAVA_HOME` |
| **.cmd 里写中文** | 整个批处理被切成碎片，`'虹綉鍏?cmd' 不是内部或外部命令` | `.cmd` **纯 ASCII + CRLF**，中文交给 Node 输出和 .md |
| **.cmd 是 LF 换行** | 同样被切碎（`'sions' 不是内部或外部命令`）——cmd.exe 的批处理解析器处理 LF-only 文件会错位 | 全部 `.cmd` 强制 **CRLF**（`_buildtools\normalize-eol.js` 统一管） |
| **.ps1 里写中文（且无 BOM）** | PS 5.1 按 GBK 读，路径变 `绱犳潗`，甚至报假的「字符串缺少终止符」 | `.ps1` **保留 UTF-8 BOM**；不需要中文的脚本就一个非 ASCII 都不留 |
| **PS 里的反引号** | 我把它当普通字符写进英文命令串，触发「字符串缺少终止符」，排查半天 | 英文命令串里禁用反引号，改成字符串拼接 |
| **沙箱里 spawn 子进程抓输出** | `execFileSync('netsh',...)` 返回 `status=null`、输出为空——沙箱禁止用管道捕获别的程序的输出 | 自检脚本**完全不 spawn**，只用 socket；读注册表那条路也放弃了（`EPERM`） |
| **沙箱里读注册表** | `C:\Windows\System32\config\SYSTEM` 直接 `EPERM`，`reg query`、`HKLM:` 提供程序全部「拒绝访问」 | 需要管理员的部分拆到 `管理自检.ps1`，由你提权跑 |
| **PowerShell/curl 的 TLS 坏了** | `SEC_E_NO_CREDENTIALS` | 下载走 Node 自带 OpenSSL（`fetch.js`） |
| **`Get-Content` 在 GBK 控制台读 UTF-8** | 中文显示成 `缃戝叧`，害我差点去改一个本来正确的文件 | 用 Node 读文件做诊断（`_buildtools\ps-quote-check.js`） |

APK 我没法在这台机器上真机跑（没有模拟器，也没有设备），所以下面这几条得你在手机上过一遍：

1. 装完打开，填地址 + 令牌，点「测试连接」应该出绿字。
2. 「回到会话」后应该看到电脑上那个 DSH 界面。
3. 发一句话给我，看电脑端会话里有没有同步出现。
4. 左边缘右滑、顶部下拉、⋮ 菜单各试一次。
5. 手机锁屏五分钟再回来，会话应该还在（网关的 cookie 是 30 天）。
